# 凹曲面功能测试验证指南

本文档说明如何分别测试验证以下三个新功能：

```text
1. 凹曲面 ROI 提取
2. 凹曲面工件坐标系建立
3. 凹曲面扫查路径规划
```

测试原则：

```text
先分模块检查中间结果，再做完整流程测试。
不要只看最终 path_map_concave.txt 是否生成。
每一步都要检查点云、矩阵、路径数量和日志。
```

---

## 1. 编译与基础单元测试

### 1.1 编译

在工作空间根目录运行：

```bash
colcon build --packages-select pointcloud_planner
```

期望：

```text
Summary: 1 package finished
```

### 1.2 运行新增模块测试

```bash
ctest --test-dir build/pointcloud_planner -R "test_(roi_mode_utils|concave_workpiece_frame|concave_path_planning)" --output-on-failure
```

期望：

```text
3/3 tests passed
```

这些测试只验证纯算法和模式隔离，不代表真实点云一定效果正确。真实效果必须继续检查下面的 PCD、矩阵和路径文件。

---

## 2. 完整运行入口

凹曲面完整流程使用：

```bash
ros2 run pointcloud_planner pcl_cloudslam --ros-args \
  -p planning_mode:=concave_surface
```

当前 `concave_surface` 流程为：

```text
pcl_filter()
  -> 手动粗框选 ROI，生成 pcl_roi.pcd
  -> refine_roi_by_platform_and_normal()
  -> fit_local_workpiece_frame_from_refined_roi()
  -> transform_refined_roi_to_workpiece_frame()
  -> path_plan_concave()
```

原有模式不应受影响：

```bash
ros2 run pointcloud_planner pcl_cloudslam --ros-args -p planning_mode:=plane
ros2 run pointcloud_planner pcl_cloudslam --ros-args -p planning_mode:=cylinder_preplan
```

## 3. 测试一：ROI 提取

### 3.1 输入

ROI 提取依赖手动粗框选得到：

```text
pcl_roi.pcd
```

该文件应包含：

```text
目标凹曲面
侧面圆柱面
部分蓝色平台
少量边缘/噪声点
```

粗框选建议：

```text
四个角落尽量落在平台上
凹曲面主体位于框选区域中间
不要框太小，否则四角平台候选点不足
不要框太大，否则无关结构混入太多
```

### 3.2 输出文件

ROI 精筛后应生成：

```text
pcl_roi_platform_candidates.pcd
pcl_roi_no_platform.pcd
pcl_roi_no_side.pcd
pcl_roi_refined.pcd
```

### 3.3 逐步检查

#### 3.3.1 检查 `pcl_roi_platform_candidates.pcd`

期望：

```text
主要是粗 ROI 四角附近的平台点
不应大量包含凹曲面主体或侧壁
点数不能太少
```

如果候选点太少：

```text
增大 corner_patch_ratio
粗框选时四角多留平台
```

如果混入工件边缘：

```text
减小 corner_patch_ratio
粗框选时让工件远离四角
```

#### 3.3.2 检查 `pcl_roi_no_platform.pcd`

期望：

```text
蓝色平台基本被去除
凹曲面和侧面仍保留
点云仍然连续，不应只剩零散点
```

如果平台残留多：

```text
增大 platform_plane_threshold
增大 roi_height_min
```

如果凹曲面被删太多：

```text
减小 roi_height_min
增大 roi_height_max
```

#### 3.3.3 检查 `pcl_roi_no_side.pcd`

期望：

```text
侧面圆柱面大部分去除
不需要扫查的圆弧过渡区被去除一部分
凹曲面主体仍完整
```

如果侧壁或过渡区残留多：

```text
增大 roi_normal_dot_min
例如 0.55 -> 0.65
```

如果凹曲面边缘被删太多：

```text
减小 roi_normal_dot_min
例如 0.55 -> 0.45
```

#### 3.3.4 检查 `pcl_roi_refined.pcd`

期望：

```text
基本只剩待扫查凹曲面
点云连续
没有大面积平台或侧壁残留
没有明显离群点
```

如果最终点云断裂：

```text
增大 roi_cluster_tolerance
减小 roi_normal_dot_min
增大 roi_normal_k
```

如果最终点云为空或过少：

```text
检查粗 ROI 是否选错
降低 roi_height_min
降低 roi_normal_dot_min
降低 roi_min_cluster_size
```

## 4. 测试二：工件坐标系建立

### 4.1 输入

工件坐标系建立依赖：

```text
pcl_roi_refined.pcd
```

该点云必须已经在机械臂基坐标系下，并且应基本只包含目标凹曲面。

### 4.2 输出文件

成功后应生成：

```text
pcl_roi_refined_workpiece.pcd
T_base_from_workpiece.txt
T_workpiece_from_base.txt
workpiece_frame_info.txt
```

### 4.3 检查 `workpiece_frame_info.txt`

重点检查：

```text
det_R
dot_xy
dot_xz
dot_yz
roi_point_count
normal_fit_point_count
used_platform_normal
```

期望：

```text
det_R 接近 1.0
dot_xy 接近 0
dot_xz 接近 0
dot_yz 接近 0
roi_point_count 足够大
normal_fit_point_count >= workpiece_min_normal_fit_points
```

判断标准：

```text
abs(det_R - 1.0) < 1e-3
abs(dot_xy) < 1e-3
abs(dot_xz) < 1e-3
abs(dot_yz) < 1e-3
```

### 4.4 检查 `pcl_roi_refined_workpiece.pcd`

期望：

```text
凹曲面中心附近坐标接近 [0, 0, 0]
中心附近局部切平面接近 X-Y 平面
曲面法向大致朝 +Z_W
点云整体形状与 pcl_roi_refined.pcd 一致，只是换到了工件坐标系
```

如果中心明显偏离：

```text
检查 pcl_roi_refined.pcd 是否包含侧壁或平台残留
调整 workpiece_center_percentile_low/high
```

如果 Z 轴方向反了：

```text
确认 ROI 提取阶段是否保存了正确 platform_normal
检查 workpiece_use_platform_normal
```

如果法向拟合失败：

```text
增大 workpiece_normal_fit_radius
增大 workpiece_normal_fit_k
降低 workpiece_min_normal_fit_points
```

## 5. 测试三：凹曲面扫查路径规划

### 5.1 输入

路径规划依赖：

```text
pcl_roi_refined_workpiece.pcd
T_base_from_workpiece.txt
```

### 5.2 输出文件

成功后应生成：

```text
path_map_concave.txt
path_map_concave_workpiece.txt
path_debug_concave.txt
```

其中：

```text
path_map_concave.txt
```

用于机械臂执行，每行格式：

```text
x y z rx ry rz
```

```text
path_map_concave_workpiece.txt
```

用于调试工件坐标系下的路径点，每行格式：

```text
x_w y_w z_w nx_w ny_w nz_w r theta phi layer_id point_id
```

### 5.3 检查 `path_debug_concave.txt`

重点检查：

```text
r_min
r_max
r_95
r_end
layer_count
total_candidate_points
valid_path_points
skipped_theta_fit_points
skipped_normal_fit_points
skipped_orientation_points
```

期望：

```text
layer_count >= 2
valid_path_points >= concave_min_total_path_points
skipped_theta_fit_points 不应远大于 valid_path_points
skipped_normal_fit_points 不应远大于 valid_path_points
skipped_orientation_points 应接近 0
```

如果 `valid_path_points` 太少：

```text
增大 concave_r_fit
增大 concave_phi_fit_deg
降低 concave_min_fit_points
增大 concave_normal_fit_radius
降低 concave_min_normal_fit_points
```

如果层数太少：

```text
减小 concave_radial_step
减小 concave_r_end
检查 r_95 是否合理
```

如果路径太密：

```text
增大 concave_scan_point_spacing
增大 concave_delta_phi_min_deg
增大 concave_radial_step
```

如果路径太稀：

```text
减小 concave_scan_point_spacing
减小 concave_radial_step
```

### 5.4 检查 `path_map_concave_workpiece.txt`

重点看：

```text
r 是否从大到小分层变化
phi 是否每层环向变化
layer_id 是否逐层递增
相邻层 phi 方向是否正反交替
nx_w ny_w nz_w 是否连续
nz_w 通常应为正
```

如果 `nz_w` 出现大量负值：

```text
检查工件坐标系 Z 轴方向
检查法向翻转逻辑
```

如果某些层缺口明显：

```text
说明该区域在 (r, phi) 邻域内点云不足
增大 concave_r_fit 或 concave_phi_fit_deg
检查 pcl_roi_refined_workpiece.pcd 是否有缺口
```

### 5.5 检查 `path_map_concave.txt`

重点看：

```text
每行是否 6 个数字
位置是否在机械臂合理工作范围内
相邻点位置是否连续
旋转向量 rx ry rz 是否没有突变
```

可用简单命令检查行数：

```bash
wc -l path_map_concave.txt
```

如果位置跳变明显：

```text
检查 path_map_concave_workpiece.txt 中相邻点是否跳变
检查 concave_enable_transition_points 是否开启
减小 concave_feed_step
```

如果姿态跳变明显：

```text
增大 concave_normal_smoothing_alpha
检查 concave_tool_z_align
检查工件坐标系 Z 轴是否稳定
```

## 6. 推荐测试顺序

### 6.1 第一次调试

```text
1. 运行 concave_surface 模式
2. 只检查 ROI 提取四个 PCD
3. ROI 合格后，再检查工件坐标系输出
4. 坐标系合格后，再检查路径规划输出
```

不要在 ROI 明显错误时调路径参数。ROI 错误会传递到坐标系和路径规划，导致后面所有结果都不稳定。

### 6.2 参数调试顺序

建议顺序：

```text
ROI 参数
  -> workpiece frame 参数
  -> concave path 参数
```

不要反过来调。

## 7. 模式隔离检查

每次修改凹曲面功能后，都要确认：

```text
planning_mode == plane
planning_mode == cylinder_preplan
```

仍然使用原流程：

```text
pcl_filter()
roi_range()
grid()
path_plan()
```

不应生成或依赖：

```text
pcl_roi_refined_workpiece.pcd
path_map_concave.txt
path_map_concave_workpiece.txt
path_debug_concave.txt
```

## 8. 常见失败定位

### 8.1 ROI 提取失败

典型表现：

```text
pcl_roi_refined.pcd 为空
凹曲面被删掉
平台或侧壁残留很多
```

优先检查：

```text
粗 ROI 是否正确
pcl_roi_platform_candidates.pcd 是否是平台
roi_height_min / roi_height_max
roi_normal_dot_min
```

### 8.2 工件坐标系失败

典型表现：

```text
workpiece_frame_info.txt 不生成
det_R 不接近 1
normal_fit_point_count 太少
pcl_roi_refined_workpiece.pcd 方向异常
```

优先检查：

```text
pcl_roi_refined.pcd 是否干净
workpiece_normal_fit_radius
workpiece_min_normal_fit_points
workpiece_use_platform_normal
```

### 8.3 路径规划失败

典型表现：

```text
path_map_concave.txt 不生成
valid_path_points 太少
skipped_theta_fit_points 很多
skipped_normal_fit_points 很多
```

优先检查：

```text
pcl_roi_refined_workpiece.pcd 是否完整
concave_r_fit
concave_phi_fit_deg
concave_normal_fit_radius
concave_min_fit_points
concave_min_normal_fit_points
```

---

## 9. 最小验收标准

一次可接受的凹曲面测试结果至少应满足：

```text
pcl_roi_refined.pcd 基本只剩目标凹曲面
pcl_roi_refined_workpiece.pcd 中心附近接近工件坐标系原点
workpiece_frame_info.txt 中 det_R 接近 1
path_debug_concave.txt 中 valid_path_points >= 20
path_map_concave.txt 每行 6 个数字
path_map_concave_workpiece.txt 中 layer_id 递增、r 大体由外向内
```

满足这些后，再进入机械臂实际执行前的可视化、碰撞和可达性检查。
